# dsh-browser-annotate

在 DSH 内置浏览器里做**页面批注**——复刻 Codex 的标注交互：页面上点选元素写批注、元素挂序号徽章、底部悬浮批注工具条；发送时批注作为**隐藏上下文**随消息带出——**会话框里不显示任何批注文本**，只有「💬 N 条注释」芯片，悬停看全文，模型读全文。

## 三个界面

**1. 页面内（被浏览的网页上）**

- 标注模式下：悬停蓝框高亮，点击元素弹出**白色批注卡**（滑杆图标 + 输入区 + 取消/保存）；**Enter 保存，Alt+Enter 换行**，中文输入法组词时的 Enter 不会误保存
- 已批注元素右上角挂**蓝色序号徽章**（①②③…），随滚动/缩放重定位，元素被 SPA 重渲染后按选择器自动找回
- 页面底部常驻**深色工具条**（可拖动）：`正在批注 · N` | 📷 页面截图 | 👁 隐藏/显示序号 | 🗑 清空全部 | **发送** | × 退出模式
- 批注模式下页面自身的点击（链接、按钮）被拦截，不会误触发

**2. 输入框工具条**

`标注` 开关（有浏览器页签时出现），带实时条数角标。

**3. 输入框上方批注卡片（编辑期）**

每条批注一张卡：**元素缩略图**（从页面截图按元素矩形裁剪）+ 标签芯片 + ✏️ 编辑（重开页面弹框）+ 🗑 删除 + 批注文本；底部 `💬 N 条注释` 胶囊。

## 发送语义

- **编辑期间输入框完全干净**：没有文字块也没有附件——批注只在托盘卡片里
- **发送时批注走「隐藏上下文注入」**：client 把批注文本 POST 进 host 信箱；agent 的 `pre-step` 瀑布（每回合第一步）把信箱内容作为一条 `source.kind: "browser-annotate"` 的 user/message 加入准入消息列表——与内置 time-context 插件的注入完全同构。聊天对非用户来源的消息**不渲染任何行**，所以**会话框里既没有原文也没有星号**，模型照常读到全文。事件由框架带真实 turn/step 写入，**结构上不可能产生游离事件**
- 你的消息本身一字不改，气泡里只有你打的话
- 转录里唯一可见的痕迹是插件渲染的 **「💬 N 条注释」芯片**（插件事件定义从带标记的上下文事件生成），**悬停/聚焦/点击弹出结构化全文**
- 空正文 + 有批注 = 可直接回车发送；页面工具条「发送」一步到位
- 信箱投递失败时发送中止，批注留在托盘不丢；发送成功后标注与页面徽章自动清空
- 空正文 + 有批注：气泡兜底显示一行标题（【页面标注 · 共 N 条】…），明细仍然隐藏
- 删除途径：卡片 🗑（单条）、工具条 🗑 / 托盘「清空」（全部）
- 📷 截图是图片附件（浏览器截图本就该是图）

模型收到的上下文消息形如：

> 【页面标注 · 共 2 条】请按标注修改，并逐条回应。
> 1. 这个按钮在手机上太小了
>    元素 button#add-meal.primary
>    选择器 body > div.card > button#add-meal
>    文本 ＋ 记一餐 ｜ 位置 (120,340) 88×32 ｜ 页面 http://localhost:5173/（减脂饮食记录）
> 2. …

## 验证

- 页面脚本：headless Chrome 真实事件驱动，**25/25 通过**（安装幂等、徽章编号/重编号、编辑 updates、untag、隐藏序号、shot/send/clear/exit 命令队列、Enter 保存 / Alt+Enter 换行 / 输入法组词保护、× 退出不杀层、stopAll 无残留）
- composer 侧：隔离 DSH 实例（0.2.1 运行时）端到端 17/20（编辑期零残留、用户正文正常上屏、**批注原文完全不出现在会话框**、注释芯片 + hover 全文、空正文兜底标题行、发送后自动消耗、模型回合无报错、无 JS 异常；3 条波动项均为测试文案诱发模型长时间工具回合的时序问题，非插件缺陷）
- **恢复验证 7/7**：发送后硬重载页面 → 日志重建无 corrupt 报错、芯片从持久事件重新渲染、原文仍不上屏；会话日志折叠校验 0 游离事件
- Trajectory 里能看到这条上下文消息（框架设计如此：模型可见的都必须可从日志重建）
- 批注超过 10 分钟未随消息发出会自动过期，不会搭到无关的回合上

## 已知限制

- 有批注未发送时，回车与发送按钮会被插件接管（用于"发送时注入"）：以 `/` 开头的指令输入不受影响；发送按钮按精确标签匹配（发送消息/排队发送/插话发送等），「编辑排队消息」不会误触
- 注释芯片渲染在其对应消息的上方
- 批注在 Trajectory（轨迹视图）里可见——它是模型上下文的一部分，框架要求一切模型可见内容可从日志重建；聊天视图按契约不渲染它
- 历史教训（2026-10-26）：更早版本在提交前自行 append `developer/message` 并猜测 turn/step，提交失败时留下游离事件导致会话日志 resume 时报 corrupt。现架构把写入权交还框架，并以「硬重载恢复」为必测项
- 恶意页面理论上可伪造批注——发送前卡片/徽章逐条可见可删
- host 半改动需重启 App 生效（本轮就是）；仅改 `client.js` 时刷新即可

## 实现与边界

- 页面脚本经 `<webview>` 的 `executeJavaScript` 注入被浏览页面自身，与页面脚本同级，不触碰 Electron/Node 能力；双向经 300ms 轮询队列通信（added/updates/removes/cmds）
- **仅桌面端**（Web 形态是跨域沙箱 iframe，注入不进去）
- 入口在 composer 工具条而非浏览器工具栏（工具栏无开放插槽，挂进宿主 DOM 违反插件规范）
- 注入走 host 半的 `POST /api/browser-annotate.inject`（信箱）+ `agent/pre-step` 瀑布（加入 decision.messages）；host 半**零外部依赖**（消息形状本地构造）
- 转录芯片由插件的事件定义匹配 `user/message` 且 `source.kind === "browser-annotate"` 生成；卸载插件后上下文仍在（模型可见、历史完整），只是不再有芯片

## 安装

**方式一：DSH 插件管理器（推荐）**

在 DSH 里打开 侧边栏 → 插件 → 安装插件，输入安装规格：

```
github:KaraChenDS/dsh-browser-annotate
```

安装后重启 App（或等宿主提示）即可在内置浏览器会话里看到「标注」按钮。

**方式二：手动 link（开发者）**

```bash
git clone https://github.com/KaraChenDS/dsh-browser-annotate.git
# 把包加入 profile 的 bundles 并以 link: 引用本地目录
```

改动 `client.js` 后刷新界面（Cmd+R）即生效；改动 `index.js`（host 半）需要重启 App（宿主 JS 不热重载）。

**卸载**：侧边栏 → 插件 → 「浏览器页面标注」→ 卸载。
